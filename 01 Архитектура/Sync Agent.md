# Sync Agent

Node.js-программа, работает как Windows Service (через `nssm.exe`) на компьютере в заведении. **Код не в git-репозитории StockFlow** — отдельный проект, файлы передаются вручную.

## Расположение и файлы

- `index.js` — точка входа, планировщик (интервалы скачивания/выгрузки), логирование.
- `sync-catalog-api.js` — синхронизация каталога товаров/техкарт через StoreHouse Web API (GGroupsTree/Goods/CmpDetails).
- `.env` — креды (`SH_API_URL`, `SH_API_USERNAME`, `SH_API_PASSWORD`, `SUPABASE_URL`, `SUPABASE_KEY` — это service_role/`sb_secret_...`, обходит RLS).

## Что делает

1. **Скачивает** файлы из Supabase Storage (`storehouse-exports`) в локальные папки `C:\StockFlow\ToStoreHouse\...`, которые вручную импортируются в StoreHouse.
   - Классификация по подпапкам (`Suppliers`, `WriteOff`, `Inventory`) — по содержимому XML или по имени файла (`classifyXml`). ⚠️ Приёмка (`Prihod_...`) классифицируется в папку **`Suppliers`**, отдельной папки "Приход" нет — контринтуитивно, но так есть.
   - После успешного скачивания файл **удаляется** из Storage и **регистрируется** в `Config/downloaded.json`, чтобы не скачивать повторно.
   - ⚠️ Имя файла приёмки строится **без времени**, только по дате+поставщику — повторные загрузки от одного поставщика в один день получат одинаковое имя и будут перезаписывать друг друга / не перескачиваться повторно (уже фиксированный риск, актуально при частом тестировании).
2. **Синхронизирует каталог** (`sync-catalog-api.js`, раз в сутки + сразу при старте): товарные группы → товары → полуфабрикаты → техкарты, эмбеддинги.
3. **Логирует** — параллельно в локальный файл `Logs\sync-agent.log` и в таблицу `sync_agent_logs` в Supabase (добавлено 02.08.2026).

## Диагностические скрипты (одноразовые, не входят в основной код)

Использовались для нащупывания структуры StoreHouse Web API — можно повторно запускать при необходимости:
- `list-groups.js` — выводит все группы товаров (`GGroupsTree`) с иерархией.
- `probe-suppliers*.js` (v1–v5) — перебор названий процедур для списка поставщиков, закончилось на `UContractors`/`UContractor` — см. [[01 Архитектура/StoreHouse API|StoreHouse API]].

## Важные технические уроки

- **Edge Functions деплоятся отдельно от фронтенда** — через Supabase Dashboard/MCP, не через git push. Легко забыть и решить, что фикс "не сработал", хотя просто не задеплоен.
- **PowerShell при сборке JSON может "распаковывать" массивы с одним элементом** — если тестируете API через PowerShell, собирайте JSON-тело как обычную строку.
- **Кириллица в cmd.exe/PowerShell может выглядеть искажённой** даже если данные в порядке — проверяйте напрямую в Supabase, не по консоли Windows.
- **JS `\b` (граница слова) не работает на кириллице** — регулярки вида `/\bбар\b/i` никогда не сработают на чисто русском тексте. Использовать разбиение на слова через `.split(/[^a-zа-яё0-9]+/i)` и сравнение целых слов.
- **`let`/`const` в strict mode — temporal dead zone** — обращение до объявления кидает `ReferenceError`, роняя процесс целиком без единой строки лога, если это происходит на самом старте. Разбираться в первую очередь при "служба падает сразу после старта, ошибок в логе нет".
- **`.env`-креды НЕ печатать в чат целиком** — только first chars для проверки типа ключа при необходимости.
