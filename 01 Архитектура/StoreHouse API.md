# StoreHouse Web API

Сервис `Sh5_webAPI_II_1` установлен на **втором компьютере** заведения (не там, где сама база StoreHouse), слушает `https://localhost:9797` (самоподписанный сертификат, старый TLS — Node нужен `rejectUnauthorized:false, minVersion/maxVersion:'TLSv1'`).

Пользователь `StockFlow`/`2580` создан через **SdbMan.exe**, права — только чтение нужных процедур (индивидуально выдаются, поэтому иногда ошибка "не найдена" на самом деле означает "нет прав", а не "процедуры не существует" — не всегда можно отличить по тексту ошибки).

Реальный IP базы StoreHouse — `192.168.1.72`, порт 7771.

Официальная документация: `docs.rkeeper.ru/sh5/api-19612347.html`, коды ошибок (частично): `docs.rkeeper.ru/archive/kody-oshibok-sdbserv-19595424.html` (диапазон **158–499 не документирован** в открытом доступе).

## Подтверждённые рабочие процедуры

| Процедура | Назначение | Параметры |
|---|---|---|
| `GGroupsTree` | Дерево товарных групп (227 групп на момент теста) | Без параметров |
| `Goods` | Товары внутри группы | `{head:'209', original:['1'], values:[[groupRid]]}` |
| `CmpDetails` | Состав техкарты по Rid комплекта | `{head:"217", original:["1","22"], values:[[komplektRid],[todayDateStr]]}` — важно: значения "по столбцам", нужна дата |
| `UContractors` | Список контрагентов (**НЕ доработано**) | Без параметров → `recCount=0`. Структура полей известна (`head="120"`: 1=Rid, 4=Guid, 14, 9, 3=Name, 2=Tin(ИНН), 12=SpecName/Alfa, 105\1/105\3=категория, 105\114\1/105\114\3=классификатор) |
| `UContractor` | Один контрагент (**НЕ доработано**) | Требует параметр (какой именно — не выяснено, падает с `Ошибка процедуры библиотеки сервера 261`, код не документирован) |

## Разбор полей Goods (для товаров/полуфабрикатов)

- `1` = Rid, `3` = название, `206\3` = единица измерения
- `215\1` = Komplekt: Rid — по НАЛИЧИЮ этого поля определяется категория "Полуфабрикат" (НЕ по полю `25`/GoodsType, оно не то, чем казалось по документации)
- Кодировка ответа сервера — обычный UTF-8, перекодировать из Windows-1251 не нужно (ошибочная гипотеза, чуть не сломали заново)

## Разбор полей CmpDetails (состав техкарты)

- `sh_id` = `210\1`, `name` = `210\3`
- брутто = `9` (QuantSpecialCmp), нетто = `53` (Quant2SpecialCmp), единица = `210\206#4\3`
- ⚠️ **НЕ использовать поле `50`** (QuantSpecCmp) — там мусор (отрицательные/нулевые числа)

## Нерешённый вопрос: поставщики

`UContractors` без параметров даёт 0 записей. Проверено напрямую через **SdbMan.exe → Прочее → Процедуры → "СОУТ МЕКСИКАНСКИЙ" [sic] → Выполнить** — тоже 0 строк. Похоже, дело не в коде StockFlow — в самом StoreHouse у контрагентов (см. окно "Корреспонденты") в колонке "Тип 1" стоит **"внешний контр. не определено"** у всех, включая протестированных. `UContractors`, вероятно, показывает только контрагентов с явно проставленным типом.

**Следующий шаг:** в SdbMan найти общий список ВСЕХ процедур сервера (искали по разделам меню "Сервис"/"Обслуживание"), поискать `Corr`/`Contr`/`Postavsh` — отложено, не доделано.

## Обходной путь (не реализован, но обсуждался)

Вместо справочника контрагентов — собирать список поставщиков из уже обработанных приходных накладных (там поставщик фигурирует как сторона документа, тип контрагента для этого не нужен).

## Полезная деталь: SQL-функции сопоставления

`match_products_by_embedding` / `match_suppliers_by_embedding` — при изменении сигнатуры **обязательно сначала `DROP FUNCTION`**, иначе Postgres может оставить две версии одновременно, и все вызовы начнут падать с "Could not choose the best candidate function".
