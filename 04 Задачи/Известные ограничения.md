# Известные ограничения

Вещи, которые не являются багами в коде, а структурные/данные-ограничения — стоит иметь в виду, чтобы не тратить время на повторный поиск причины.

## Данные StoreHouse

- **Дубли техкарт по названию** — распространённое явление, не единичный случай. См. [[02 Модули/Списания]] и [[02 Модули/Техкарты]].
- **Опечатки в названиях веток** — напр. "ОБРАБОТКИ" vs "ОТРАБОТКИ БАР" (разные слова, не связаны напрямую).
- **Некоторые техкарты неполные** (пример: "Соус Халапеньо П/Ф" — только соль в составе).
- **У контрагентов не проставлен тип** ("внешний контр. не определено") — из-за этого справочник поставщиков через API пока недоступен.

## Ограничения расчётов

- **Раскрытие полуфабрикатов — приблизительное, не эталонное.** "Выход" партии считается как сумма нетто-весов ингредиентов, потому что поле `yield_weight` у техкарт-полуфабрикатов почти всегда пустое.
- **Допущение 1г≈1мл / 1л≈1кг** — стандартное для общепита, не идеально точное для всех жидкостей, но другого способа сравнить весовые/объёмные величины в одной пропорции нет.
- **Конвертация "штуки → вес" принципиально невозможна без явного указания веса единицы** — сознательное решение НЕ гадать формулу (см. обсуждение "тесто на бельгийские вафли", 300г мороженого "1 шт" в накладной).

## Инфраструктурные

- **Edge Functions деплоятся отдельно от git-пуша фронтенда** — не забывать деплоить вручную через Supabase MCP/Dashboard.
- **Имя файла приёмки без времени** — риск коллизии при повторных загрузках от одного поставщика в один день (актуально в первую очередь при тестировании).
- **Классификация папок Sync Agent контринтуитивна** — приёмка попадает в папку "Suppliers", не "Приход"/"Delivery".
- **Нет данных о продажах** (R-Keeper не подключён) — невозможно фильтровать "актуальные" техкарты по факту продаж, только по структуре StoreHouse.

## Безопасность / доступ

- **RLS одинаковый для всех ролей** — разделение owner/manager/employee только на уровне интерфейса, не в базе.
- **Токены доступа (GitHub, и т.п.) стоит выпускать с минимальными правами и коротким сроком действия**, отзывать сразу после использования — практика, принятая в этом проекте с самого начала.
