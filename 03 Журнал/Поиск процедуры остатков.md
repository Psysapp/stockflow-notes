# Поиск процедуры для остатков (current_stock) и живых запросов

⚠️ **Относится к Компьютеру 2** (там, где стоит `Sh5_webAPI_II_1` и `sync-catalog-api.js`) — см. [[01 Архитектура/Sync Agent]].

## ✅ РЕШЕНО (04.08.2026) — через официальную документацию

Процедура **`GRemns`** ("Ведомость остатков") — найдена через официальный справочник процедур r_keeper, не угадыванием. Полная спецификация — см. [[01 Архитектура/Справочник процедур StoreHouse]]. Проверка (`probe-gremns.js`) подготовлена/выполняется.

## Контекст

`current_stock` в `sh_products` никогда не синхронизируется (найдено 03.08 через ИИ-чат/BalancePage) — 94% пустые, оставшиеся 6% тестовые фейковые данные. Нужна отдельная процедура StoreHouse API (по аналогии с тем, как нашли `Price0`/`Price1` для цен).

Заодно эта же процедура понадобится для **живых запросов** через `sync_agent_requests` (см. [[02 Модули/ИИ-ассистент]]) — идея пользователя: не делать много отдельных синхронизаций, а сразу подготовить и остатки, и живые запросы, и уточнить цены одним пакетом при следующем перезапуске службы.

## Кандидаты (найдены 04.08.2026 через полный просмотр списка процедур в SdbMan, присланный архивом скриншотов)

Приоритет по убыванию:
1. **`GoodsRemainsList`** — прямое название "список остатков товаров"
2. **`VStock`** — короткое, видимо "остаток" (не было галочки прав в списке — может понадобится проверить права отдельно)
3. **`RepVStock`** — "отчёт по остаткам"
4. **`GoodsPrices`** / **`ODocGoodsPrices`** (эта отмечена ✓, есть права) — альтернатива/дополнение к уже найденным `Price0`/`Price1` из `Goods`

Также по пути в том же списке процедур встретились (менее приоритетные, но на заметку):
- `DivAccSums` / `DivAccSums2` — возможно, "суммы по подразделению"
- `RepGoodsSost` — "состояние товаров"
- `ODocRemnsLst` (не до конца уверен в точном прочтении названия по скриншоту)

Скрипт `probe-remains.js` подготовлен (проверяет все 5 кандидатов через `sh5struct` + пустой вызов) — **не запущен**, компьютер пользователя был занят. Ждём следующего раза.

## План после того, как найдём рабочую процедуру

Одним пакетом, один перезапуск службы:
1. Код для `sync-catalog-api.js` — синхронизация `current_stock` при обычном цикле (как уже сделано для `purchase_price`).
2. Код для Sync Agent — обработчик `sync_agent_requests` (забирает pending-заявки, дёргает найденную процедуру по конкретному `sh_id`, пишет результат обратно).
3. В `hyper-service` — включить ожидание готового ответа (сейчас заявка создаётся, но ответ не ждётся).
4. Заодно установить уже готовый код с ценами (`Price0`/`Price1`), который ждёт с утра.
