# Приглашения новых сотрудников — RLS блокировала автопринятие (10.08.2026)

## Симптом

Пользователь приглашал нового сотрудника (Максим Киселёв, роль employee). Тот регистрировался, но **даже после выхода и повторного входа** попадал на экран "Нет приглашений". Пользователь отметил, что это **повторяющаяся** проблема ("снова").

## Корень проблемы — найден точно

У таблицы `invitations` была **единственная** RLS-политика: `is_org_manager(organization_id)`, применённая ко ВСЕМ действиям (SELECT/INSERT/UPDATE/DELETE).

Это значит: чтобы просто **увидеть** приглашение, человек уже должен быть менеджером той организации. Но только что приглашённый — по определению ещё **не состоит** в организации. Замкнутый круг, воспроизводится **на 100%**, для каждого нового приглашённого — не изредка, а всегда.

Это ломало сразу два места:
1. **`NoOrgPage.tsx` → `loadInvites()`** — SELECT из `invitations` возвращал пусто (RLS блокировала), ошибка **проглатывалась молча** (`catch { /* silently fail */ }`) — экран показывал "Нет приглашений" вместо настоящей причины.
2. **`authStore.ts` → `tryAutoAcceptInvitation()`** (добавлено 01.08.2026 для автопринятия при каждом входе) — делала ТОТ ЖЕ самый SELECT, тоже блокировался, тоже тихо сдавался (`if (!invite) return;`) — вот почему "даже после выхода и входа снова" не помогало: функция честно пыталась при каждом входе, просто физически не видела приглашение.

`organization_members` при этом была настроена правильно (`user_insert_own`, `with_check: true` — любой залогиненный может вставить себя) — эта часть цепочки не была виновата.

## Исправление

Миграция `fix_invitations_rls_for_invited_user` — добавлены две новые политики на `invitations`:
- SELECT: `(auth.jwt() ->> 'email') = email` — человек видит приглашения, адресованные его собственному email.
- UPDATE: то же условие — может пометить своё же приглашение принятым (`accepted_at`).

Не даёт доступа к чужим приглашениям — только к своим, по совпадению email из токена.

Плюс в `NoOrgPage.tsx` убрано молчаливое проглатывание ошибок — теперь показывается реальный текст ошибки, если что-то подобное повторится в будущем, это будет видно сразу, а не потребует расследования с нуля.

## Конкретный пострадавший восстановлен вручную

Максим Киселёв (`makskiselcs2006@gmail.com`) — добавлен в `organization_members` напрямую, приглашение помечено принятым. С этого момента новые приглашённые должны проходить автоматически при обычном входе — RLS больше не блокирует.
