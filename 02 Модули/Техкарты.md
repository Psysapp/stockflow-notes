# Модуль: Техкарты

## Два независимых источника синхронизации

1. **`storehouse_ttk_import`** (старый способ) — Edge Function `import-techcards` разбирает печатные отчёты "Технологическая карта", которые Sync Agent выгружает в Storage. **Не содержит информации о группе/кухня-бар** — источник в принципе этого не знает. ~802 карты на момент анализа. `category` при повторном импорте НЕ трогается (сохраняет ручную классификацию).
2. **`storehouse_api_sync`** (новый способ) — `sync-catalog-api.js` в Sync Agent, через прямой Web API StoreHouse (обходит группы GGroupsTree, товары Goods, состав CmpDetails). ~2604 карты. `category` **перезаписывается при каждом запуске** — это и позволило ретроактивно переклассифицировать все существующие карты одним фиксом (см. ниже).

## Кухня/бар (решено 02.08.2026)

В дереве групп StoreHouse реально есть разделение: `Полуфабрикаты` (кухня, без явного слова "кухня" в названии — это дефолт) vs `Полуфабрикаты бар` (явно помечено словом "бар"). Аналогично `Товары`→`Товары кухня`/`Бар`, `Меню ресторана`→`Кухня`/`Бар`.

**Реализация:** `resolveDepartment(groupRid, groupsByRid)` в `sync-catalog-api.js` — идёт вверх по цепочке родительских групп, ищет слово "бар" или "кухня" **по целому слову** (не через `\b` — не работает на кириллице, см. [[01 Архитектура/Sync Agent|Sync Agent]] — через явное разбиение на слова). Матчинг по НАЗВАНИЮ, не по rid — портируемо на новые организации с другой нумерацией групп.

**Результат на реальных данных:** 2604 карты → bar: 1136 / kitchen: 1468. Подтверждено на конкретных примерах (джин/коктейли/латте → bar).

**Не покрыто:** 802 карты через `storehouse_ttk_import` остаются в "kitchen" по умолчанию — печатная форма не даёт данных о группе.

## "Мусорные" ветки → is_active: false (решено 02.08.2026)

Ветки, технически создающие техкарты, но не являющиеся блюдами меню: `НЕ ИСП`/`Не использовать`, `Персонал`, `ОБРАБОТКИ`, `Хоз. товары`. Реализовано через `isExcludedBranch()` — та же логика хождения по дереву, что и `resolveDepartment`. Карточки из этих веток создаются как обычно (данные не теряются), но `is_active: false` — интерфейс (`TechCardsPage`) уже фильтрует по `is_active=true`, скрытие происходит без изменений на фронтенде.

На реальных 227 группах под исключение попало 30 групп.

## Отложено: "Версия N" дубли (803 карты)

Пользователь явно попросил **не трогать** пока — заняться сначала кухня/бар. Позже выяснилось (в контексте списаний), что дубли по имени — не просто визуальный бардак, а функциональная проблема (раскрытие рецептов может пойти по неверной карточке), см. [[02 Модули/Списания|Списания]]. Вопрос об удалении/объединении дублей в самом StoreHouse **остаётся открытым**.

## Другие находки

- 25 дублирующихся названий помимо версионных (напр. "Оливье" ×3, "Уха" ×3).
- 7 карт с префиксом "не исп..." — кандидаты на удаление, финального подтверждения от пользователя не было.
- `tech_card_ingredients.product_id` ссылается на пустую таблицу `products` (мёртвый FK) — см. [[01 Архитектура/База данных|База данных]].
