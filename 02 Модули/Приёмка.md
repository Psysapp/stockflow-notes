# Модуль: Приёмка

Файл: `src/modules/tma/delivery/DeliveryPage.tsx`. Сценарий: camera → staging → scanning (Gemini/Groq распознают фото накладной) → review → saving → (опционально) confirm_upload → done.

## Конвейер сопоставления товаров

1. `scan-invoice` (Edge Function) — распознаёт фото накладной, достаёт позиции.
2. `match-product` (Edge Function) — сопоставляет каждую позицию с товаром каталога. Раздельные кандидаты на каждую позицию батча (см. журнал), Gemini основной / Groq запасной.
3. Точное совпадение по имени и кэш (`ai_match_cache`) проверяются до похода к ИИ.
4. Конвертация единиц измерения (`convertToCanonicalUnit`, общая с списаниями) — автоматически только для безопасных случаев (г↔кг, мл↔л, вес↔объём по допущению 1г≈1мл). Для несовместимых семейств (напр. "шт" накладной vs "кг" каталога) — **не гадаем**, показываем экран `confirm_upload` с предупреждением и двумя кнопками ("Выгрузить как есть" / "Не выгружать").

## Генерация XML

`generateDeliveryXml` (`xmlGenerator.ts`). Каждая строка накладной — отдельная позиция в файле (даже если несколько позиций ведут на один и тот же `sh_id` — раньше объединялись, теперь по явному запросу пользователя НЕ объединяются, см. журнал 03.08).

Номер накладной: поле `f67` (`TTN_number`) корректно берёт `invoice_number`. Поле `f65` раньше содержало случайный `pointerId` (баг, исправлен) — теперь тоже `invoice_number`.

## Диагностика проблем

- **`xml_upload_log`** — аудит каждой попытки выгрузки в Storage (реальная проверка через повторный список файлов, не просто доверие ответу SDK).
- Если файл "пропал" — проверять по цепочке: `xml_upload_log` (записался ли и подтвердился ли) → `sync_agent_logs` (скачал ли Sync Agent, в какую подпапку) → реальная папка на компьютере (`ToStoreHouse\Suppliers`, не "Приход"!).

Не относится напрямую к приёмке товаров (это про техкарты), см. [[02 Модули/Техкарты|Техкарты]].

## Крупная переделка: сопоставление товаров видно ДО выгрузки (05.08.2026)

**Найдено:** сравнение реальной накладной (сфотографированной, 21 позиция) с XML, который сгенерировала приёмка, показало 6 из 21 позиций (29%) ушли неопознанными (`sh_id=0`). Проверка показала: система вела себя правильно (отказалась гадать между похожими товарами вроде "Стакан бумажный 300мл" / "Стакан 300мл прозрачный" / "Стакан шейкер 300мл прозрачный"), но у сотрудника **не было возможности** это увидеть и поправить — сопоставление с каталогом (`match-product`) происходило только в момент нажатия "Выгрузить", уже ПОСЛЕ экрана проверки, невидимо для человека.

**Фикс:** вынес логику сопоставления (`matchCatalog`) в отдельную функцию, вызываемую СРАЗУ после сканирования — до показа экрана проверки. Экран проверки теперь показывает по каждой позиции:
- ✅ зелёная галочка + название, если сопоставлено уверенно;
- 🟠 кликабельные кнопки-варианты (та же механика, что в ИИ-чате), если ИИ нашёл несколько похожих кандидатов — сотрудник выбирает сам одним тапом;
- ⚠️ жёлтое предупреждение "не найден в каталоге", если совсем ничего не нашлось — видно СРАЗУ, а не постфактум.

`handleConfirm` (кнопка "Подтвердить") больше не делает повторный поход в `match-product` — просто собирает XML из уже готового, видимого сотруднику результата.

**Побочная находка при сверке:** название поставщика на бумажной накладной ("Триал Маркет") не совпало с тем, что записалось в XML ("Триал Макс") — стоит присмотреться отдельно, не разобрано до конца в эту сессию.
