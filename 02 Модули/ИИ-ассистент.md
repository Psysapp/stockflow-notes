# Модуль: ИИ-ассистент (главный экран)

`src/modules/tma/ai/AIChatPage.tsx` — первый экран после входа (`ROUTES.AI_CHAT`, редирект из роутера). Backend — Edge Function `hyper-service` (Groq, `llama-3.1-8b-instant`, настоящий function calling).

## Архитектура

- **Чтение** (query_stock, query_techcard) — выполняется на сервере (service role, SELECT, org-scoped).
- **Запись** (create_writeoff, create_task) — сервер только готовит `actions[]`, реальная запись — на клиенте, под сессией сотрудника (RLS применяется как обычно, не по доверию к ИИ).
- Доступные инструменты зависят от роли (employee не видит `query_stock`/`create_task`, как и в обычном меню).

## Найденный и исправленный баг (03.08.2026)

`create_writeoff` писал **напрямую в устаревшие плоские поля** таблицы `write_offs` (`product_name` как текст, без сопоставления с каталогом вообще). У таблицы есть ДВА параллельных набора полей — старые (`product_name`,`qty`,`unit`,`comment`) и актуальные (`items` jsonb, `reason`, `department`, `exported_to_sh`). `WriteOffsPage.tsx` при выгрузке в StoreHouse имеет fallback на старые поля, но там **жёстко стоит `sh_id: 0`** — то есть любое списание из ИИ-чата гарантированно уходило в StoreHouse неопознанным.

**Фикс:** `create_writeoff` теперь вызывает `match-product` (та же процедура, что в приёмке) для поиска реального товара, конвертирует единицы через `convertToCanonicalUnit`, пишет в актуальную схему (`items[]`). Если товар не опознан уверенно — предупреждает в чате явно, а не создаёт молча сломанную запись.
