# Долгосрочный ориентир: "свой Джарвис" для StockFlow

Сформулировано пользователем 11.08.2026: конечная цель развития ИИ-ассистента StockFlow — не просто отвечающий чат-бот, а полноценный "Джарвис", разбирающийся во всей экосистеме организации (StockFlow + StoreHouse + r_keeper + всё остальное, что подключено).

## Зачем эта заметка

Держать как направляющий принцип при планировании каждой следующей доработки ИИ — сверяться "к какому из трёх слоёв ближе то, что делаем сейчас", а не добавлять возможности хаотично.

## Три слоя пути к цели

### 1. Расширять зрение — ИИ видит всё больше экосистемы
Уже видит: остатки, техкарты, задачи, приёмки, чек-листы, историю закупок (см. [[02 Модули/ИИ-ассистент]]).
Дальше по мере готовности инфраструктуры: реализация из r_keeper в реальном времени (см. [[01 Архитектура/r_keeper — расчётный остаток]]), инвентаризации, себестоимость блюд, данные по сотрудникам.
Принцип расширения тот же, что уже отработан: найти реальный источник данных → честно подключить → научить ИИ пользоваться, без выдумывания.

### 2. Проактивность — сам говорит, а не только отвечает
Пока ИИ только реагирует на вопрос. Следующий рубеж — фоновый механизм, который сам замечает и сообщает ("заканчивается сыр", "теоретический расход разошёлся с фактическим — возможна порча"). Сырьё для этого уже есть (история закупок/продаж/остатков) — не хватает именно механизма фонового наблюдения и инициативы. **Ещё не начато.**

### 3. Доверие на самостоятельные действия
Сейчас: ИИ либо читает данные, либо готовит действие, которое подтверждает человек (create_writeoff/create_task). Настоящая автономность — по цене ошибки, постепенно: сначала дешёвые обратимые вещи (задачи), затем при накоплении истории надёжности — более значимые действия. Не форсировать раньше времени — риск реальных потерь на складе, не игровая ошибка.

## Как этим пользоваться в будущих сессиях

При любой новой идее для ИИ-ассистента — сверяться: это расширение зрения (слой 1), шаг к проактивности (слой 2), или шаг к автономности (слой 3)? Если непонятно, к какому слою относится — вероятно, стоит уточнить у пользователя ценность идеи, прежде чем реализовывать.
